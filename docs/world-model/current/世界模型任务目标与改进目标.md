# GPPO 世界模型任务目标与改进目标

> 状态：设计基线，尚不代表功能已经实现或通过验收  
> 讨论沉淀日期：2026-09-02  
> 依据：EAWM 论文 *From Observations to Events: Event-Aware World Model for Reinforcement Learning*（arXiv:2601.19336v1）及 GPPO-8.29 当前代码边界

## 1. 总目标

在不替换 GPPO、不削弱现有动作合法性和并发安全约束的前提下，引入一个**动作条件、事件感知、面向异构图的世界模型**，使系统能够：

1. 从历史 belief 图、已执行动作和已到达证据中形成时序潜状态；
2. 预测不同动作可能造成的下一图状态、事件、收益、成本和终止概率；
3. 在信息延迟、通信缺失和部分可观测条件下，为 GPPO 提供历史与趋势信息；
4. 在模型可靠后，通过短期 imagined trajectories 提高 GPPO 的样本效率与规划能力；
5. 保持 GPPO 作为唯一动作决策器，保持真实 `action_mask`、版本校验、ACK、lease 和 fencing 等执行约束的权威性。

目标架构：

```text
可信 belief 图 G_t + 历史动作 a_<t + 已到达证据
                         ↓
       Graph Event-Aware World Model
       ├─ 时序潜状态 [h_t, z_t]
       ├─ 下一图状态/图差分预测
       ├─ 自动事件概率
       ├─ reward/cost/continuation 预测
       └─ 不确定度
                         ↓
       GPPO Actor-Critic + 真实 action_mask
                         ↓
        候选 UAV-Region 边或 NOOP
                         ↓
       版本、ACK、lease、fencing 校验后执行
```

## 2. 核心定义与分工

### 2.1 世界模型如何训练

EAWM 整体属于模型式强化学习框架，但世界模型参数本身主要通过预测损失训练，而不是通过 PPO 策略梯度训练。

训练样本应至少包含：

```text
(G_t, history_t, executed_action_t, G_{t+1}, reward_t,
 cost_t, event_t+1, done_t, metadata_t)
```

世界模型的建议目标函数为：

```text
L_WM = λ_state L_state
     + λ_event L_event
     + λ_reward L_reward
     + λ_cost L_cost
     + λ_done L_continuation
     + λ_cal L_calibration
```

- `L_state`：下一潜状态、图差分或关键节点/边属性预测；
- `L_event`：自动事件预测，连续/有序特征可用交叉熵，稀疏事件可用 Focal Loss；
- `L_reward`、`L_cost`：任务收益和多目标代价预测；
- `L_continuation`：回合继续或终止预测；
- `L_calibration`：约束概率和不确定度可解释，避免把高置信错误直接交给策略。

### 2.2 GPPO 如何训练

GPPO 仍使用强化学习训练：

```text
L_GPPO = PPO clipped policy loss
       + value loss
       - entropy bonus
```

第一阶段只把冻结世界模型产生的潜状态作为 GPPO 辅助输入。后续通过验收后，才允许在世界模型生成的短期 imagined trajectories 上辅助训练 Actor/Critic。

### 2.3 事件在这里是什么

事件不要求人工逐帧标注。训练时可由相邻状态自动生成伪标签：

- 有序特征：显著上升、下降或不变；
- 类别特征：类别改变或保持；
- 图结构：节点/边新增、失效、关系变化；
- 任务语义：任务出现、完成、取消、优先级或工作量显著变化；
- 平台语义：UAV 故障、能力下降、恢复；
- 通信语义：链路变化、超时、迟到证据或同步完成。

自动事件预测首先是**表示学习辅助目标**。它不等于人工事件偏好，也不应在未验证前直接控制动作或通信。

### 2.4 动作由谁选择

- 训练世界模型时，输入的是数据中**已经执行的动作**；
- 在线运行时，候选动作仍由 GPPO 自主选择；
- 世界模型只预测“给定该动作后可能发生什么”；
- 世界模型不绕过 GPPO 单独下发动作。

## 3. 当前问题与改进目标

### I-01：从无动作历史预测改为动作条件预测

**问题**：如果模型只读取历史状态，不读取动作，就无法区分不同 UAV-Region 分配造成的后果。

**改进目标**：所有动力学预测必须显式条件化于 `executed_action_t`；动作编码应覆盖候选边、NOOP、动作是否合法以及动作执行结果。

**验收**：打乱动作后，验证集下一状态、事件或 reward 预测应显著变差，证明模型确实使用了动作信息。

### I-02：从全局摘要向量升级为异构图时序表示

**问题**：均值摘要会丢失 UAV、区域、任务和关系级差异。

**改进目标**：复用 GPPO 的节点、边和类型定义构建 Graph Encoder，再通过 GRU、Transformer 或 RSSM 维护时序潜状态。

**验收**：与“摘要向量 + GRU”基线比较，报告节点/边状态误差、事件 F1 和下游 GPPO 指标。

### I-03：将事件头对齐 EAWM 的自动事件与 GES

**问题**：单一语义事件分类无法覆盖连续变化、结构变化和多模态稀疏事件。

**改进目标**：

1. 从相邻可信状态自动生成事件标签；
2. 按模态设置独立事件头；
3. 使用 GES 或等价的事件密度门控平衡观测/状态预测与事件预测；
4. 将自动事件头与可选的语义事件头分离。

**验收**：报告无事件、单事件、连续事件、重叠事件和 burst 场景的分类指标与校准指标。

### I-04：补齐 reward、cost、continuation 和 uncertainty 预测

**问题**：只有下一潜状态和事件类别，不能支持动作后果比较或 imagined trajectories。

**改进目标**：增加 reward、多目标 cost、continuation/done 和 uncertainty heads。

**验收**：在 episode 级严格划分的验证集上报告 MAE/RMSE、AUROC/F1、ECE/Brier score；禁止使用随机样本切分造成轨迹泄漏。

### I-05：把世界模型从通信触发器扩展为 GPPO 辅助表示

**问题**：仅用“有事件概率”决定是否通信，没有利用世界模型学习到的历史潜状态帮助动作选择。

**改进目标**：第一版接入只向 GPPO Actor/Critic 提供：

```text
[h_t, z_t, event_probability_t, uncertainty_t]
```

真实图仍是策略主输入，Event Predictor 输出默认不直接进入 actor；需要直接使用事件概率时必须单独做消融。

**验收**：与原始 GPPO 和“仅历史 GRU”比较，在相同训练预算、随机种子和评估事件带下报告结果。

### I-06：建立不确定度门控和安全回退

**问题**：世界模型会遇到分布外状态和不可预测的外生事件。

**改进目标**：

- 高不确定度时退回原始 GPPO；
- 预测图不得写回正式 belief；
- 预测结果不得直接修改真实 `action_mask`；
- 迟到或未确认信息不得伪装成已确认状态；
- 保留旧 checkpoint 和无世界模型运行模式。

**验收**：关闭世界模型后行为与原始 GPPO 一致；注入错误预测时不产生非法动作、状态越权或并发协议破坏。

### I-07：在基础闭环通过后增加短期想象训练

**问题**：长轨迹预测会累积误差，随机故障和通信事件也可能没有可观测前兆。

**改进目标**：从 1 至 3 步 imagined rollout 开始，只作为 Actor/Critic 的辅助训练数据；不得直接替代真实评估。

**验收**：同时报告 1、3、5 步预测误差；只有短期 imagined training 在独立测试场景显著优于冻结 latent 接入时，才扩大 horizon。

## 4. 实施任务

### T-00：冻结基线和数据合同

- 固定可复现的 GPPO checkpoint、配置、种子和评估事件带；
- 定义 transition schema、张量形状、缺失值语义和版本字段；
- 明确训练可用的离线真值与部署可用输入，建立无泄漏检查。

**完成标准**：数据 schema 有版本号，随机、贪心和 GPPO 轨迹均能通过同一 recorder 写入并重放。

### T-01：采集覆盖性轨迹

- 混合随机合法策略、贪心策略和已有 GPPO；
- 覆盖 normal、single、sequential、overlap、burst、弱通信和长信息间隔场景；
- 记录实际执行动作，而不是只记录策略建议动作；
- 按 episode/场景/seed 划分训练、验证和测试集合。

**完成标准**：生成数据清单、事件分布、动作覆盖率和切分哈希。

### T-02：实现 Graph World Model 基线

- Graph Encoder；
- 动作编码器；
- 时序动力学；
- 下一状态、reward/cost、continuation 和 uncertainty heads；
- 离线训练与独立评估入口。

**完成标准**：可以从保存数据独立训练、恢复 checkpoint，并完成一步预测评估。

### T-03：实现 EAWM 事件感知训练

- 自动事件生成器；
- 多模态事件头；
- GES/事件密度门控；
- Focal Loss/交叉熵及损失权重配置；
- `WM`、`WM+Event`、`WM+Event+GES` 消融。

**完成标准**：事件辅助目标改善表示或下游指标；若没有改善，应保留负结果，不将其表述为已验证收益。

### T-04：Shadow mode 与校准

- 在线读取可信 belief 和历史动作，但不影响 GPPO 决策；
- 记录预测、真值、置信度、额外延迟和失败原因；
- 完成分布内、分布外和弱通信压力测试。

**完成标准**：满足预测质量、校准、时延、无泄漏和安全门槛后才能进入策略接入。

### T-05：冻结 latent 接入 GPPO

- 冻结世界模型；
- 向 Actor/Critic 增加可选 latent adapter；
- 保持真实图、候选边和 NOOP 语义不变；
- 支持配置关闭和旧 checkpoint 兼容。

**完成标准**：原始 GPPO、历史 GRU、WM-GPPO 和 EAWM-GPPO 在相同协议下完成消融。

### T-06：短期 imagined trajectories

- 使用 GPPO 产生候选动作；
- 世界模型滚动预测下一潜状态和 reward/cost；
- 从 1 至 3 步 horizon 开始训练 Actor/Critic；
- 限制模型数据占比并执行不确定度截断。

**完成标准**：独立测试场景提升且安全指标不退化；否则保持 T-05 方案。

## 5. 推荐实验矩阵

| 组别 | 图策略 | 世界模型 | 事件头 | GES | imagined rollout |
|---|---|---|---|---|---|
| GPPO | 是 | 否 | 否 | 否 | 否 |
| GPPO-History | 是 | 仅历史编码 | 否 | 否 | 否 |
| WM-GPPO | 是 | 是 | 否 | 否 | 否 |
| EA-noGES-GPPO | 是 | 是 | 是 | 否 | 否 |
| EAWM-GPPO | 是 | 是 | 是 | 是 | 否 |
| EAWM-Imagine-GPPO | 是 | 是 | 是 | 是 | 1-3 步 |

主要指标：

- 任务：完成率、makespan、任务收益、多目标 cost；
- 事件：macro-F1、各事件 recall、误报率；
- 状态预测：节点/边 MAE、结构变化 F1；
- 校准：ECE、Brier score、风险-覆盖曲线；
- 通信：通信次数、字节量、过期信息比例；
- 系统：推理 P50/P95/P99、非法动作数、安全回退次数；
- 泛化：未见 seed、未见事件组合、长信息间隔和 burst 场景。

## 6. 明确不做的事情

当前阶段不将以下内容视为已授权或已完成：

1. 用世界模型替换 GPPO；
2. 用预测图覆盖正式 belief 图；
3. 用预测结果绕过真实 `action_mask`；
4. 假设完全随机、无前兆外生事件可以被准确提前预测；
5. 在基础一步预测尚未校准时进行长 horizon 规划；
6. 将自动事件预测等同于人工偏好奖励；
7. 因为增加了世界模型就宣称系统延迟降低。世界模型增加计算开销，它只能缓解通信延迟或缺失信息造成的影响。

## 7. 完成定义

本任务只有同时满足以下条件才可称为“世界模型已经迁移到 GPPO”：

- 有动作条件、异构图输入和严格序列切分的数据闭环；
- 世界模型在独立测试集完成状态、事件、reward/cost、continuation 和校准评估；
- GPPO 能在配置开关下读取冻结 latent，并能无损退回原始模式；
- 预测信息不污染 belief、action mask 或执行并发协议；
- 完成至少 GPPO、GPPO-History、WM-GPPO、EAWM-GPPO 四组公平消融；
- 所有性能结论均有 checkpoint、配置、seed、日志和结果表支持。

在此之前，应使用“设计中”“原型”“shadow mode”或“实验性接入”等准确状态描述。
