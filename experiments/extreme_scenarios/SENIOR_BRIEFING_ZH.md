# 向学姐汇报：minimum-validation 与极端多事件压力测试

## 一句话结论

我已经完成两模型 minimum-validation 的合同、训练与证据闭环，并在不修改正式证据的独立分支上增加了多任务、多事件、临时变化和信息不完整的极端压力测试。现有结果不支持“GPPO 在所有场景统一优于 PPO”，但显示 GPPO 在搜索/跟踪资源强争用、等待未来资源释放的场景有明确研究价值；持续事件风暴和严格实时场景目前仍更偏向 PPO 或在线规划器。

## 已经完成的工作

1. 将 minimum-validation 合同统一为 PPO-MLP、GPPO-Adaptive 两个模型，三个训练 seeds，每个 run 50k steps，固定使用 50k checkpoint，不做 checkpoint selection。
2. 完成 6/6 runs、12/12 checkpoints 的训练证据封存，固定评估集合为六个 50k checkpoints。
3. 完成 100-case、五场景、三训练 seed 的固定 checkpoint held-out 对比，并归档完整结果、配对统计和 SHA-256 inventory。
4. 在独立实验 worktree 中设计七类极端场景，共 42 条 paired tapes；运行两个学习模型及四种确定性基线，共 420 个回合。
5. 额外验证事件在“推理完成—动作提交”之间到达时，旧动作会被 graph/action version 机制拒绝，不消耗 reward 或 decision step，随后能够基于新图重新决策。

## 正式 minimum-validation 的主要结果

- PPO 与 GPPO 的总体事件成功率、合法覆盖率和 episode return 接近，没有形成稳定的总体胜负。
- PPO 的归一化距离稳定更低，平均推理约 `2.51 ms`；GPPO 约 `17.07 ms`，实时成本明显更高。
- GPPO 在 Sequential、Overlap、Burst 出现回报正向趋势，但只有三个独立训练 seeds，置信区间不足以支持普遍优越性声明。
- Test-Unseen 没有显示 GPPO 的结构编码能够自动解决分布外或信息延迟问题。

## 极端场景的新发现

### 1. 跟踪饱和与延迟释放是 GPPO 最有价值的场景

三架 UAV 进入 TRACK、最后一架搜索 UAV 损毁、等待未来目标销毁释放资源时，GPPO 相对 PPO：

- 恢复延迟减少约 `0.678`；
- 累计空缺减少约 `12.817`；
- episode return 增加约 `0.610`；
- 三个训练 seed 的上述方向一致。

代价是归一化距离增加约 `0.024`，推理慢约 `12.37 ms`。Current-Pending Exact Planner 在该场景的恢复延迟和累计空缺还略优于 GPPO，说明“学习策略 + 小规模规划器兜底”值得继续研究。

### 2. 事件很多并不意味着 GPPO 必然更好

在八事件持续风暴中，GPPO 的累计空缺、距离、负载差和回报均没有超过 PPO，并且推理慢约 `11.59 ms`。这说明当前两层局部图消息传递没有自动解决长事件链问题。

### 3. 信息乱序不能只靠图网络解决

因果报告乱序下两种前馈模型基本打平。当前模型缺少事件历史、信息年龄、报告置信度和 belief state，所以后续若研究信息不完整，应引入 GRU/R2D2、recurrent QR-DQN 或显式状态估计，而不是单纯加深 GNN。

### 4. 成功率已被环境约束顶到天花板

七类压力测试中所有策略最终成功率都是 100%。这主要来自 action mask、合法性约束和恢复机制，因此下一阶段不能再把成功率作为唯一主指标，应重点比较累计空缺、恢复延迟、距离、负载、尾部风险和端到端时延。

## 我对项目现状的判断

这个项目目前已经从“能不能完成两模型训练”推进到“什么场景真正需要图策略”的阶段。现有证据更适合支持以下表述：

> GPPO 不是 PPO 的全面替代品，而是面向强关系耦合和资源争用状态的候选策略；PPO 仍是固定小图和严格实时场景的可靠基线。

项目当前最大的研究缺口不是继续堆训练步数，而是：

1. 当前图规模固定为 4 UAV、4 Region、3 Target，尚未验证动态规模和拓扑泛化；
2. 两个学习模型都是前馈策略，没有真正解决部分可观测性；
3. 当前 reward 与累计空缺等业务指标并不始终同向，单看 episode return 会掩盖持续空缺代价；
4. 当前 Exact Planner 只处理现有 pending regions，没有滚动预测未来释放事件；
5. 极端场景是看到原结果后设计的开发集，不能直接升级成新的 held-out 结论。

## 下一步建议

建议建立新的、与旧合同完全隔离的研究分支，优先实现三个候选：

1. **Beam-MPC / Rolling-Horizon Planner**：规划 3–5 个决策步，每层保留 8–16 个候选，显式处理未来任务释放；这是目前最有直接证据支持的方向。
2. **Planner-Distilled MLP**：用规划器生成专家动作，再通过行为克隆与 DAgger 蒸馏，目标是保留规划质量并接近 PPO 的推理速度。
3. **Recurrent QR-DQN/R2D2**：面向乱序、延迟、缺失信息，引入历史记忆和回报分布，重点优化尾部风险。

开发阶段可以使用本次 42 条极端 tapes，但算法和阈值冻结后，必须生成未见过的 Extreme-V2 hidden bank 做一次性验证。建议验收条件为：成功率 100%、最终不可行率 0、累计空缺相对 PPO 降低至少 10%、恢复延迟降低至少 5%，同时距离与负载恶化不超过 5%，并满足端到端 P95 时延约束。

## 建议的口头汇报版本

> 我这阶段先把两模型 minimum-validation 的合同和证据链做完整了。现在是 PPO-MLP 和 GPPO-Adaptive，各三个 seed、每个 50k steps，六个 run 和十二个 checkpoint 都有 SHA 和 provenance，评估固定使用 50k checkpoint，没有做选择。正式 100-case 对比显示两者总体成功率和回报接近，PPO 的距离和推理时延更好，GPPO 只在部分并发场景出现趋势，所以目前不能说 GPPO 全面优于 PPO。
>
> 为了更贴近实际的多任务、多事件、临时更改和信息不完整，我又在独立分支设计了七类极端场景，做了 42 条事件带和 420 个回合。最清晰的发现是，在搜索和跟踪资源争用、需要等待未来资源释放时，GPPO 三个 seed 都比 PPO 恢复更快、累计空缺更少；但在八事件持续风暴和任务快速反复时，PPO 仍然更稳。报告乱序时两个模型基本打平，说明信息不全需要记忆或 belief state，单靠图网络不够。
>
> 所以下一步我不建议直接加训练步数，而是优先做带未来释放预测的 Beam-MPC，再考虑把规划器蒸馏成快速 MLP，同时用 recurrent QR-DQN 研究信息不完整。新的算法会在新的 hidden extreme bank 上一次性验证，不复用现在这批开发场景做最终结论。

## 汇报时应避免的表述

- 不说“GPPO 已经全面优于 PPO”；现有数据不支持。
- 不把这批 post-hoc 极端场景称为新的正式 held-out test。
- 不只展示成功率；它已经是 100% 天花板。
- 不把一次回报提升解释为所有业务指标都改善。
- 不承诺当前模型已经解决信息缺失；目前只验证了版本保护和观测后的恢复。
