# 极端场景结果解读

## 主要结论

1. **所有方法在 42 条 tapes 上均达到 100% 事件成功率和 100% 最终合法覆盖率。** 这不代表极端场景没有压力，而是说明当前 action mask、可行性约束和环境恢复机制把合法性兜住了。模型差异主要表现为恢复速度、累计空缺、距离、负载和推理延迟。
2. **GPPO 最明确的优势出现在 `tracking_saturation_release`。** 相对 PPO，三个训练 seed 均表现为恢复更快、累计空缺更少、回报更高；均值分别为恢复延迟 `-0.678`、累计空缺 `-12.817`、回报 `+0.610`。代价是归一化距离 `+0.024`，且推理慢约 `12.37 ms`。
3. **持续事件风暴更偏向 PPO。** `event_storm_8` 中 GPPO 的恢复延迟 `+0.014`、累计空缺 `+0.555`、距离 `+0.0367`、负载差 `+0.1305`、回报 `-0.186`，同时慢约 `11.59 ms`。这说明当前两层 GPPO 并没有因为事件更多就自动获益。
4. **任务反复变更也没有体现 GPPO 优势。** `task_churn` 中 GPPO 虽把累计空缺减少 `0.055`，但回报下降 `0.302`，距离和负载略差；三个训练 seed 的回报差均不支持 GPPO。
5. **报告乱序下两种前馈模型基本打平。** `out_of_order_reports` 的回报差只有 `-0.036`，并且 seed 方向混合。这符合架构预期：两者都没有事件历史记忆或 belief state，图编码器本身不能解决因果报告乱序。
6. **资源坍缩出现目标冲突。** GPPO 回报高 `1.142`、恢复快 `0.078`，但累计空缺多 `1.282`、距离多 `0.0151`。这说明只看 episode return 会掩盖持续空缺代价，实际选型必须明确指标优先级。
7. **推理延迟始终是 GPPO 的稳定代价。** 七种场景中 GPPO 比 PPO 慢约 `9.08–12.37 ms`。

## 与确定性策略的比较

- `tracking_saturation_release`：Current-Pending Exact Planner 的恢复延迟 `6.20`、累计空缺 `95.20`，略优于 GPPO 的 `6.29` 和 `97.49`，适合小规模、可审计的临时不可行情形。
- `event_storm_8`：Greedy Cost 的回报 `22.897`、恢复延迟 `1.953`，优于 PPO 和 GPPO，但它只做当前一步代价优化，不能据此推断长期全局最优。
- `resource_collapse`：Greedy Cost 的累计空缺 `8.510` 最低；GPPO 为 `10.294`。
- 简单或动作空间被强约束的场景中，PPO 经常与 Min Load 产生相同或近似结果，说明当前固定 4×4 图下仍有较强的规则可替代性。

## 策略选择建议

- 搜索/跟踪资源争用、存在“暂时无可用搜索 UAV、等待未来释放”的场景：优先继续验证 GPPO；安全关键时使用 Exact Planner 兜底。
- 八事件持续风暴、任务快速反复切换、严格实时：当前优先 PPO 或 Greedy Cost，不应仅因为事件多就选择 GPPO。
- 报告乱序、消息缺失、长时间信息盲区：当前两个模型都不够，需要新增事件历史、信息年龄和置信度特征，或使用 GRU/belief-state；本次结果不能证明 GPPO 能解决信息不全。
- 若业务把累计未覆盖时间放在最高优先级，不应仅按 episode return 选择策略。
